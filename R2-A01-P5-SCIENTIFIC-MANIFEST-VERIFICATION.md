## 6. Self-Referential Commit-SHA Artifact Policy

### Problem Statement:
If a scientific manifest file containing the Git commit SHA is committed to the repository, creating that commit produces a new Git commit SHA. This immediately invalidates the SHA recorded inside the committed manifest, resulting in a permanent circular inconsistency.

### Ratified Policy:
1. **Execution-Time Generation:** The scientific manifest is designated as an **execution-time reproducibility artifact** generated dynamically during verification runs, test suites, and scientific release packaging.
2. **Generator as Canonical Tool:** The generator script (`tools/generate_scientific_manifest.py`) is the version-controlled canonical tool tracked in the repository.
3. **No Static Manifest Commit:** The manifest JSON itself is not tracked as a static file in Git. At verification or build time, `python tools/generate_scientific_manifest.py -o <target_path>` writes the artifact for consumption by scientific pipelines.
4. **Runtime Integrity Verification:** Pipelines and auditors can verify any recorded manifest artifact against the repository using:
   ```bash
   python tools/generate_scientific_manifest.py --check <manifest_path>
   ```
